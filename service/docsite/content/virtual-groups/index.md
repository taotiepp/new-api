# 虚拟分组

虚拟分组是你自己的模型目录。它没有倍率，也没有渠道。请求会按你指定的来源分组和来源模型选渠道、计费。令牌分组和 `分组名/模型名` 的用法见 [模型调用](/app/docs/model-calling)。

在控制台打开「虚拟分组」，添加一个分组，再从你已经能使用的分组里选来源模型。不同来源分组的模型可以放进同一个虚拟分组。例如 `claude-opus-5-5` 的来源分组是 `aws`，`gpt-6-luna` 的来源分组是 `codex`。调用这两个名称时，分别按各自的来源分组和来源模型处理。

同一个来源模型可以写多个别名，用来替换调用方原来使用的模型名。客户端用这些别名调用时，网关都按这个来源模型处理，发给上游的模型名也是来源模型。

例如来源分组是 `aws`，来源模型是 `claude-opus-5-5`，别名写成 `opus`。令牌的分组选成这个虚拟分组后，直接请求别名：

```bash
curl {{server_address}}/v1/chat/completions \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "opus",
    "messages": [{"role": "user", "content": "Hello"}]
  }'
```

这条请求按 `aws` 分组和 `claude-opus-5-5` 选渠道、计费，上游收到的模型名也是 `claude-opus-5-5`。

令牌仍使用原来的分组时，把模型写成 `虚拟分组名/别名`，例如 `coding/opus`。模型名以分组名开头，且这一段是你的虚拟分组时，优先走这个虚拟分组。否则使用令牌当前的分组。当前分组是真实分组、模型名也没有虚拟分组前缀时，请求保持原样。

令牌限制可用模型时，按客户端写下的名称判断。令牌分组是虚拟分组时，模型列表返回该分组里的这些名称。

分组名不能和已有分组或 `auto` 相同，不能包含空格或 `/`。每个账号最多 20 个虚拟分组，每个分组最多 100 个模型。同一分组里的名称不能重复。来源分组必须是你已经能使用的真实分组。
